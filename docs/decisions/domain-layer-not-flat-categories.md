# 加一层「域」，而不是把新分类摊平进 categories.toml

> 日期: 2026-08-22
> 状态: 采纳
> 关联: [typed-content-model-not-hugo](typed-content-model-not-hugo.md)（前提：分类法用 newtype，引用完整性硬失败）

## Context

目录原本只收自托管**可观测**工具，分类法因此只有一层，且那一层的名字就叫「信号分类」——
指标 / 日志 / 链路 / 告警。首页的第一根轴是「按你要替换掉哪个 SaaS」。

范围要扩到 homelab 全栈技术选型（计算底座、网络与接入、存储与备份、交付与 GitOps、
密钥、身份、安全、IaC、数据服务）之后，这两个前提同时失效：

- **「信号分类」这个词不再成立**：CNI 不是一种信号，hypervisor 也不是。
- **SaaS 轴覆盖不到一半内容**：CNI、hypervisor、GitOps 控制面这类条目压根没有对应的
  SaaS 可替换。把 SaaS 索引留在首屏第一位，等于让首屏漏掉一半目录。

需要决定的是分类法的**形状**，不是要不要扩内容。

## Options

### 1. 平铺：把 CNI、入口、备份、密钥后端直接加进 `categories.toml`

零代码改动，最省事。否决理由三条：

- 首页变成 30 多项**彼此不可比**的清单 —— 「日志」和「hypervisor」并列，读者没有任何
  依据判断先看哪个。
- 分类页的「换个分类」会从 CNI 跳到日志。那不是换分类，是换话题。
- 分类名在不同语境下含义不同：`backup` 在存储域指 restic/Velero，在可观测域会被理解成
  指标的长期存储。平铺之后没有任何机制能表达这个区别。

### 2. 多值 `domain`（一个工具可属多个域）

Cilium 确实同时是 CNI、网络策略与流量可观测；Harbor 既是镜像仓库也做漏洞扫描。
按「谁真实覆盖了哪些域」建模最贴近事实。否决理由：

- **条目数不再可加**：首页每个域卡片上的「N 条」互相重叠，加起来不等于目录总数，
  那个数字就失去了「值不值得点进去」的意义（它是卡片上唯一的信息量）。
- 面包屑没有唯一父级 —— 工具页要么挂多条路径，要么随便挑一条，两者都比单值更差。

### 3. 单值 `domain` + 域内分类（采纳）

域是第一根轴，分类挂在域下面，且分类必须与条目同域。

### 4. 用自由 tag 取代分类法

直接违背 [typed-content-model-not-hugo](typed-content-model-not-hugo.md) 的立场：
tag 是自由文本，写错一个字母就是静默生成一个空页面 —— 那正是当初换掉 Hugo 的原因。
不再复述。

## Decision

采纳选项 3：

- 新增 `content/domains.toml`（`id` / `name` / `tagline`），**声明顺序即首页顺序**，
  且那个顺序本身是一条内容判断：先有底座，才有跑在上面的东西。
- `Tool.domain`：单值、必填、非 `Option`。跨域的工具只登记**主域**，另一面写进 `detail`。
- `Category.domain`：必填。无主分类会在首页变成一个不知该挂在哪的入口。
- 校验从四类扩到五类，新增的两类都是硬失败：
  - 域引用未声明（拼错一个字母，条目就从所有导航里消失）；
  - **跨域分类** —— `domain = "networking"` 的条目引用了可观测域的分类。
    两个引用各自都存在，只有组合是错的，这正是纯 `String` 分类法查不出的那一类。
  - 孤儿检查同时覆盖分类与域（零条目的域点进去是一张空页面）。
- 路由加 `/domains/{id}`；工具页面包屑从域起（域 → 分类 → 条目）。
- 首页第一根轴换成域，SaaS 索引降为第二根轴 —— 后者仍然有效，只是不再覆盖全集。

## Consequences

**得到的：**

- 加一个域的成本是「写一段声明 + 写够条目」，不改一行代码。
- 「域内条目数」可加、可比，覆盖不均看得见 —— `xtask validate` 按域打印条目数，
  哪个域薄是打印出来的事实，不是需要有人去数的印象。
- 多出一类构建期就能挡住的错误（跨域分类），而它在平铺方案里根本无法表达。

**付出的：**

- **单值域迫使跨域工具丢掉一半身份**：Cilium 登记在网络域，读者从「安全加固」域里
  找不到它；Harbor 的漏洞扫描能力同理。这是有意接受的取舍 —— 换来的是可加的计数与
  唯一的面包屑父级。缓解手段只有 `detail` 里的一句话，不是机制。
- 既有 29 条条目全部要补 `domain` 字段，`categories.toml` 每条要补归属。一次性迁移。
- `DeployKind` 顺带加了 `Manifests` 与 `OsImage` 两个变体：hypervisor 与不可变 K8s 发行版
  装的是操作系统，不是「一个包」，硬塞进 `DebRpm` 会让读者以为能 `apt install`。

**新出现的问题（留给 ROADMAP，不在本 ADR 解决）：**

- FieldNote 的覆盖率被稀释了。段 3 原定「10 条 FieldNote」是对着 29 条可观测条目定的
  目标，现在分母是 97 条 —— 目标该表述成「先把可观测那一域做满」还是「每个域至少一条」，
  是一个新的开放项。⚠️ 不要因为域变多了就去为没跑过的工具编造 FieldNote：
  覆盖不均是诚实的，见 [field-notes-as-differentiator](field-notes-as-differentiator.md)。
